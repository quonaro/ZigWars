# StringHashMap: ключи-строки

## Хеш-таблица для строк

`std.StringHashMap(V)` — специализация хеш-мапы, где ключ `[]const u8`, а хеш и сравнение — по **содержимому** строки, а не по указателю:

```zig
var map = std.StringHashMap(void).init(alloc);
defer map.deinit();

try map.put("hello", {});          // значение-void: просто множество
_ = map.contains("hello");         // true
_ = map.contains("world");         // false
```

В отличие от ArrayList — мапа **managed**: хранит аллокатор внутри себя, методы вызываются без него. `init(alloc)` + `deinit()` — обычная пара.

`StringHashMap(void)` — идиоматичный «сет строк»: `void`-значение занимает ноль байт, а `put(k, {})` означает «добавить в множество».

## API, который нужен постоянно

```zig
try map.put(k, v);                 // вставить или перезаписать
map.get(k);                        // ?V — значение или null
map.contains(k);                   // bool
const gop = try map.getOrPut(k);   // слот: существующий или новый
if (!gop.found_existing) {
    gop.value_ptr.* = initial;     // заполнить новое значение
} else {
    gop.value_ptr.* += 1;          // увеличить существующее
}
map.count();                       // число пар
```

`getOrPut` — рабочая лошадка для счётчиков: одна операция вместо пары `contains`+`put` (экономит одно хеширование и одно обращение к таблице).

## ⚠️ Ключи и время жизни

Мапа **не копирует ключ** — хранит срез `[]const u8` как есть. Если память под ключом умрёт — ключ мапы станет висячим:

```zig
// ПЛОХО: s — локальный буфер, ключ сдохнет после выхода
var s: [32]u8 = ...;
try map.put(&s, {});

// ХОРОШО: ключ из входных данных, которые живут дольше мапы
// или выдели копию:
const owned = try alloc.dupe(u8, key);
try map.put(owned, {});
// и освободи все owned-ключи при разборе мапы!
```

В задачах вроде «посчитать слова входной строки» ключи — это **подстроки входа**: они ссылаются в `s`, живут пока живёт `s`, и `dupe` не нужен. Дедупликации ключей это тоже помогает: одно и то же слово на разных позициях — разные срезы, но `StringHashMap` сравнивает по содержимому — всё сработает.

## Разбиение строки на слова

```zig
var it = std.mem.tokenizeAny(u8, s, " \t\n");
while (it.next()) |word| {
    // word — подстрока s без разделителей
}
```

`tokenizeAny` пропускает все перечисленные разделители и выдаёт непустые куски. Регистр важен: `"Hello"` и `"hello"` — разные слова. Для регистронезависимого счёта ключи пришлось бы нормализовать (с `dupe`, раз ключ новый).

## Производительность

Хеш-мапа — амортизированный O(1) на операцию. Для `wordCount` это O(символов) всего. Альтернатива — отсортировать слова и посчитать уникальные, O(n log n) + память на сортировку.
