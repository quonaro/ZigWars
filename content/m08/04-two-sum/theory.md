# AutoHashMap: хеш-таблица для любых ключей

## Generic-мапа

`std.AutoHashMap(K, V)` — managed-мапа, которая умеет хешировать почти любые «простые» типы ключей автоматически: числа, enum'ы, bool, строки-байты... (для `[]const u8`-ключей чаще берут `StringHashMap` — она специально заточена).

```zig
var map = std.AutoHashMap(i32, usize).init(alloc);
defer map.deinit();

try map.put(7, 3);          // ключ 7 → значение 3
map.get(7);                 // ?usize = 3
map.get(8);                 // null
map.contains(7);            // true
map.count();                // 1
```

`Auto` — значит «подбери хеш-функцию сам» через `std.hash.autoHash`. Структуры и указатели имеют подводные камни (указатель хешируется по адресу, а не содержимому) — для них есть `std.HashMap` с явным контекстом. Для чисел и enum'ов `Auto` — то что нужно.

## `getOrPut` — один поиск вместо двух

Классика «вставить если нет, получить если есть»:

```zig
const gop = try map.getOrPut(key);
if (gop.found_existing) {
    // gop.value_ptr.* — уже лежащее значение
} else {
    // свежий слот, value_ptr указывает на неинициализированное значение —
    // заполни обязательно!
    gop.value_ptr.* = something;
}
// gop.key_ptr.* — ключ, который в мапе
```

Важно: `value_ptr` валиден только до следующей вставки в мапу (рехеш инвалидирует указатели). Получил — используй сразу.

## Идиома: «число → индекс»

Хеш-таблица отлично строит «обратный индекс» массива — значение → где оно лежало:

```zig
var seen = std.AutoHashMap(i32, usize).init(alloc);
for (xs, 0..) |x, i| {
    try seen.put(x, i);    // последняя позиция каждого значения
}
```

## Two Sum: почему O(n) вместо O(n²)

Задача: найти два индекса `i < j` таких, что `xs[i] + xs[j] == target`.

Наивно — двойной цикл, O(n²) по времени и O(1) по памяти.

Хитро: идём один раз. Для элемента `x` на позиции `i` искомый партнёр — `target - x`. Если он уже **встречался раньше** (лежит в мапе) — ответ найден: индекс из мапы + текущий `i`. Если нет — кладём `x → i` в мапу и идём дальше. O(n) по времени, O(n) по памяти.

```zig
for (xs, 0..) |x, i| {
    const need = target - x;
    if (seen.get(need)) |j| return .{ j, i };  // j < i автоматически!
    try seen.put(x, i);
}
return null;
```

Обрати внимание на элегантность: раз мы проверяем «был ли партнёр _до_ меня», порядок индексов `j < i` получается даром, и пара «два одинаковых значения на разных позициях» корректно находится.

## Подводные камни `AutoHashMap`

- `map.get(k)` возвращает `?V`, а `map.getPtr(k)` — `?*V`: для чтения-записи значения бери `getPtr`.
- После `put`/`getOrPut` старые `_ptr` — трупы: не храни их.
- `deinit()` обязателен: мапа владеет своими бакетами.
