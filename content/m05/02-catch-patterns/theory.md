# `catch` — оператор, а не блок

## Выражение, а не конструкция

В языках с исключениями `catch` — блок, ловящий «что угодно откуда угодно». В Zig `catch` — **бинарный оператор**, применённый к одному выражению:

```zig
const v = exprВозвращающийErrorUnion catch запаснойПлан;
```

Если `expr` вернул ошибку — результат всего выражения будет `запаснойПлан`. Это `orelse` для ошибок — синтаксис тот же, семантика та же: «достань значение или вот запасное».

```zig
const n = std.fmt.parseInt(i64, s, 10) catch 0;
```

`std.fmt.parseInt(T, text, base)` парсит число из строки; на мусоре и переполнении возвращает ошибку.

## `catch |err|` — посмотреть, что именно упало

Запасной план может быть блоком, где ошибка доступна через пайп:

```zig
const n = parseInt(i64, s, 10) catch |err| blk: {
    std.debug.print("парсинг упал: {s}\n", .{@errorName(err)});
    break :blk -1;
};
```

`@errorName(err)` — имя ошибки строкой, удобно для логов.

## `try` — это catch-однострочник

Повторим ключевое тождество:

```zig
const v = try expr;
// ≡
const v = expr catch |err| return err;
```

`try` значит «мне тут нечего с этой ошибкой делать — пусть разбирается вызывающий». Ошибка остаётся видимой в сигнатуре функции — никакой магии.

## `catch unreachable` — опасная уверенность

```zig
const v = expr catch unreachable;
```

«Эта ошибка невозможна». Если соврал — в Debug/ReleaseSafe получишь panic (что честнее, чем UB), в ReleaseFast — неопределённое поведение. Используй, только когда невозможность доказана кодом: например, парсишь строку, которую сам же только что проверил валидатором.

Второй вариант — `catch @panic("описание")`: падает всегда, но хотя бы с сообщением и не отключает проверки в ReleaseFast.

## Когда что выбирать

- `try` — ошибка не моя, пробрасываю (по умолчанию).
- `catch fallback` — есть осмысленное значение по умолчанию (кеш, конфиг, парсинг пользовательского ввода).
- `catch |err| switch` — разные ошибки по-разному: `FileNotFound` терпимо, `OutOfMemory` — нет.
- `catch unreachable` — инвариант доказан, и ты готов отвечать за него.
- `expectError` в тестах — проверить, что ошибка действительно та.

## Глотать молча — последнее дело

`catch {}` или `catch return` без логирования — тот же `except: pass`, просто явный. Плюс в том, что в Zig это видно в коде при ревью; минус тот же — ошибка исчезла бесследно.
