# std.Io.Writer — куда угодно, одинаково

`std.Io.Writer` в Zig 0.17 — это интерфейс «приёмник байтов». В него можно писать в файл, в сетевой сокет, в буфер в памяти — API одинаковый. Сама структура `Writer` — это vtable + состояние; конкретные реализации подставляют свою логику записи.

## Три основных Writer'а

| Реализация | Куда пишет | Когда использовать |
|-----------|-----------|-------------------|
| `.fixed(&buf)` | В готовый `[]u8` буфер | Известен максимальный размер, аллокаций нет |
| `Allocating` | В растущий буфер через аллокатор | Строим строку, не зная размера |
| `file.writer(io, ...)` | В файл | Стриминг без сбора строки |

## `Writer.fixed`

```zig
var buf: [128]u8 = undefined;
var w: std.Io.Writer = .fixed(&buf);
try w.print("x = {d}", .{42});
const written = w.buffered(); // "x = 42" — сколько реально записали
```

Переполнение буфера — `error.NoSpaceLeft`. Отлично для стека-памяти и предсказуемых размеров.

## `Writer.Allocating` — собираем строку

Когда размер неизвестен (таблица, отчёт, JSON), `Allocating` растит буфер сам:

```zig
var aw: std.Io.Writer.Allocating = .init(alloc);
defer aw.deinit();
try aw.writer.print("{s}: {d}\n", .{name, n});
const s = try aw.toOwnedSlice(); // забираем строку себе
// aw больше не владеет буфером — free за нами
defer alloc.free(s);
```

- `aw.writer` — поле-интерфейс `std.Io.Writer`, через него пишем.
- `toOwnedSlice()` — «отдать» накопленное как `[]u8` (после этого `aw` пуст и `deinit` ничего не трогает — но вызывать всё равно можно).
- `getWritten()` — текущий буфер без передачи владения.

## `print` — форматный вывод

Синтаксис формата: `{[аргумент][спецификатор]}`.

| Спецификатор | Тип | Пример |
|-------------|-----|--------|
| `{s}` | строки, байты | `print("{s}", .{"hi"})` |
| `{d}` | целые десятичные | `print("{d}", .{42})` |
| `{x}` | hex | `print("{x}", .{255})` → `ff` |
| `{e}` | scientific | `print("{e}", .{1.5})` |
| `{any}` | любой тип — структуры, массивы | `print("{any}", .{my_struct})` |
| `{d:>5}` | ширина 5, выравнивание вправо | `print("{d:>5}", .{42})` → `"   42"` |
| `{s:<8}` | ширина 8, влево | `print("{s:<8}", .{"ab"})` → `"ab      "` |

Выравнивание через `:` и `<`/`>`/`^` — готовая таблица без ручных пробелов.

## Зачем `Allocating`, а не `alloc.print`?

`alloc.print` создаёт строку одним вызовом — удобно для одного `print`. `Allocating` нужен, когда строка строится **итеративно**: циклы, условия, вложенные вызовы `print`. Буфер растёт по мере записи, а `toOwnedSlice` в конце отдаёт ровно столько, сколько записали.
