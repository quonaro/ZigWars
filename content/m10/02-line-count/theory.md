# Сколько строк в файле — и как их считать

## Определение «строки»

Утилита `wc -l` считает количество `\n`. Это значит, что файл `a\nb` — «одна строка с точки зрения wc», хотя людей она смущает. Мы в этом kata используем более дружелюбное определение:

> **lines = (число `\n`) + 1, если файл не пуст и не заканчивается на `\n`**

| Содержимое | `\n` | Строк |
|------------|-----|-------|
| `""` | 0 | 0 |
| `"a"` | 0 | 1 |
| `"a\n"` | 1 | 1 |
| `"a\nb"` | 1 | 2 |
| `"a\nb\n"` | 2 | 2 |
| `"a\n\n"` | 2 | 2 |
| `"\n"` | 1 | 1 |

Последняя незаконченная строка считается строкой. Пустой файл — ноль.

## Читаем файл целиком

Для таких задач проще всего прочитать весь файл в память:

```zig
const data = try cwd.readFileAlloc(io, path, alloc, .limited(1 << 20));
defer alloc.free(data);
```

`readFileAlloc` возвращает владельческий `[]u8` — его обязательно освобождай `alloc.free`. Затем `std.mem.count(u8, data, "\n")` даст число разделителей.

## `std.mem` — швейцарский нож для байтов

- `std.mem.count(u8, haystack, needle)` — вхождения подстроки;
- `std.mem.findScalar(u8, data, '\n')` — первый индекс байта (в 0.17 `indexOf*` переименован в `find*`);
- `std.mem.tokenizeScalar(u8, data, '\n')` — итератор по непустым токенам между разделителями;
- `std.mem.startsWith` / `endsWith` — проверки краёв.

`tokenizeScalar` пропускает пустые участки — для подсчёта строк он не подходит (`"a\n\nb"` даст два токена, а строк три). Считай `\n` — надёжнее.

## Стриминг как альтернатива

Читать файл целиком — не всегда можно: файл может быть гигабайтным. У `File` есть `f.reader(io, &.{})` — буферизованный `std.Io.Reader`, который тянет данные кусками. Он позволяет читать строки по одной (`streamUntilDelimiter`-подобные методы менялись между версиями — смотри `std.Io.Reader` в std) и не держать весь файл в памяти. Для kata проще `readFileAlloc` — но помни, что это компромисс «простота ↔ память».
