# Optional как честная сигнатура

## Сигнатура как контракт

В C функция деления может вернуть магическое значение (`-1`?), бросить исключение (C++) или уронить программу (деление на ноль — UB). Смотришь на `int divide(int a, int b)` — и не знаешь, что будет при `b == 0`.

В Zig ответ прямо в типе:

```zig
pub fn safeDiv(a: i32, b: i32) ?i32
```

«Возвращаю либо `i32`, либо ничего». Вызывающий **обязан** обработать оба случая — `?i32` нельзя засунуть туда, где ждут `i32`. Компилятор — твой ревьюер, который никогда не отвлекается.

## Полная форма `if` по optional

```zig
if (opt) |v| {
    // opt был «что-то», v — это само значение (тип i32, не ?i32)
} else {
    // opt был null
}
```

Одна конструкция делает и проверку, и распаковку. Никакого `if (x != null) { use(*x) }` с ручным разыменованием — null-проверка и доступ к значению неразрывны.

`if` — выражение, значит можно вернуть значение целиком:

```zig
const report = if (safeDiv(10, 2)) |q| q else -1;
```

## Optional или ошибка?

Частый вопрос: когда `?T`, а когда `!T` (error union, следующий модуль)?

- `?T` — «результата может не быть, и это нормальная ситуация». Поиск не нашёл, кеш пуст, список кончился.
- `!T` — «что-то пошло не так, есть конкретная причина». Файл не открылся, память кончилась.

Деление на ноль — спорная граница. Здесь мы выбрали `?i32`: ноль — законное значение параметра, «нет результата» — законный исход. В следующем модуле сделаем то же через `error{DivisionByZero}` и сравним ощущения.

## Сравнение с null

`null` — полноценное значение: его можно сравнивать (`x == null`), хранить, возвращать:

```zig
if (b == 0) return null;
return @divTrunc(a, b);
```

Обрати внимание: `@divTrunc` — деление с усечением к нулю (как `/` в C). Обычный `/` для знаковых целых в Zig не компилируется — язык заставляет выбрать семантику явно: `@divTrunc`, `@divFloor` или `@divExact`.
