# Функции как параметры и `?usize` против `?T`

## Функция — тоже значение

В Zig функции можно передавать как аргументы. Тип выглядит так:

```zig
fn(i32) bool        // «функция: i32 на входе, bool на выходе»
fn(i32, i32) i32    // два аргумента
```

Передаёшь просто именем — без `&`, без звёздочек:

```zig
fn isPositive(x: i32) bool {
    return x > 0;
}

const f: fn(i32) bool = isPositive;
const ok = f(3);            // true
const ok2 = isPositive(-1); // и напрямую, конечно
```

Это **не** замыкания: `fn` — голый указатель на код, захватить локальные переменные он не может. Для замыканий в Zig есть другие приёмы (comptime-структуры, `*anyopaque` + vtable) — но для колбэка-предиката `fn` хватает за глаза, и это zero-cost.

## `?usize` или `?T`?

Вернёмся к поиску. Классика C — вернуть `-1` как «не нашёл». В Zig индексы — `usize`, беззнаковые: `-1` туда не засунешь, а магические константы типа `std.math.maxInt(usize)` — так себе читаемость. Поэтому идиома — optional:

```zig
fn indexOf(xs: []const i32, needle: i32) ?usize {
    for (xs, 0..) |x, i| {
        if (x == needle) return i;
    }
    return null;
}
```

Но что возвращать — индекс или сам элемент?

- `?usize` — вызывающий сам решит, что делать с позицией: прочитать соседа, удалить элемент, заменить его. Гибче.
- `?T` — проще, когда позиция не нужна, важен только найденный объект.

Оба валидны; выбирай по тому, что нужно потребителю API. В стандартной библиотеке чаще вернут индекс/слайс — например, `std.mem.findScalar` отдаёт `?usize`.

## Захват `|v|` ещё раз

```zig
if (indexOf(xs, 7)) |i| {
    // i: usize — позиция, не значение!
    std.debug.print("нашёл на {d}\n", .{i});
}
```

Легко перепутать: `|v|` распаковывает **то, что вернула функция**. Вернула индекс — в пайпах индекс. Вернула элемент — в пайпах элемент.

## `while` тоже умеет optional

Не только `if`: `while (opt) |v|` крутится, пока optional не станет `null`. Именно так работают итераторы стандартной библиотеки (`it.next()` возвращает `?Item`). Подробнее — в следующем kata.
