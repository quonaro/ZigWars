# Optionals: `?T` — честный null

## Проблема: ошибка на миллиард

Тони Хоар, изобретший null-ссылку, называл её «ошибкой на миллиард долларов». В C любой указатель может внезапно оказаться `NULL`, и компилятор молчит — до сегфолта в проде.

Zig решает это типом: обычный `*i32` **не может быть null никогда**. Если значение может отсутствовать — тип обязан это признать: `?i32`, `?*Node`, `?[]u8`.

## `?T` — optional-тип

```zig
var a: i32 = 5;
var b: ?i32 = 5;    // «может быть i32, а может — ничего»
var c: ?i32 = null; // пусто

a = null;  // ошибка компиляции! обычный i32 не бывает null
b = null;  // ок
```

`null` — единственное «отсутствующее» значение, и оно живёт только внутри `?T`.

## Три способа достать значение

**1. `orelse` — с запасным вариантом:**

```zig
const v = maybe orelse default;      // v: i32, не ?i32
const v = maybe orelse return;       // или выйти из функции
const v = maybe orelse unreachable;  // «я уверен» — упадёт, если null
```

**2. `.?` — «я знаю, что там есть»:**

```zig
const v = maybe.?;  // panic, если null (в Debug/ReleaseSafe)
```

Это честный `unwrap`: в отличие от сегфолта, ты получишь понятную панику с трассировкой.

**3. Захват в `if` — безопасный и идиоматичный:**

```zig
if (maybe) |v| {
    // v — i32, null уже отфильтрован
} else {
    // maybe был null
}
```

Синтаксис `|v|` — тот же пайп-захват, что в `for (xs) |x|`: значение «выгружается» в новую переменную.

## Optional-указатели бесплатны

`?*T` занимает столько же места, сколько `*T`: адрес 0 играет роль null. А вот `?i32` — уже больше (значение + флаг): любой бит `i32` может быть валидным числом, «свободного» значения для null нет.

## Почему это фича

Сигнатура `fn find(...) ?Item` честно говорит: «могу ничего не вернуть». Забыть проверить нельзя — `?Item` не передашь туда, где нужен `Item`, компилятор не даст. Null-проверка перестаёт быть делом дисциплины и становится делом системы типов.
