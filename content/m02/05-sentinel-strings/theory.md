# Sentinel-типы: метка конца

## Проблема: где конец строки?

Слайс знает длину. А C-строка — нет: это голый указатель `char*`, и конец помечается **сентинелом** — байтом `0` («нуль-терминированная строка»). Чтобы узнать длину, C идёт по байтам, пока не упрётся в ноль. Если нуля нет — читает чужую память (привет, классика уязвимостей).

Zig встраивает сентинел **в тип**, сохраняя гарантию на уровне компилятора.

## Синтаксис сентинелов

```zig
[N:0]T      // массив из N элементов + элемент-страж со значением 0 после них
[*:0]T      // многоэлементный указатель, за которым гарантированно есть 0
[:0]T       // слайс, за последним элементом которого стоит 0
```

Значение сентинела может быть любым (`[N:255]u8`), но `0` — стандарт для строк.

```zig
const arr: [5:0]u8 = .{ 'h', 'e', 'l', 'l', 'o' };
// в памяти шесть байт: h e l l o 0
// arr.len == 5, но arr[5] == 0 — сентинел доступен по индексу len!
```

Строковый литерал `"hello"` в Zig уже нуль-терминирован: его тип — `*const [5:0]u8`. Поэтому он легко отдаётся и как `[]const u8`, и как `[*:0]const u8`, и в `printf` напрямую.

## `[*:0]const u8` — «C-строка, которой можно доверять»

Многоэлементный указатель `[*]u8` не знает длины. `[*:0]const u8` — тоже не знает, но **гарантирует**: где-то впереди стоит `0`. Это позволяет:

```zig
const s: [*:0]const u8 = "hello";
s[4]   // 'o'
s[5]   // 0 — сентинел можно читать!
s[6]   // ??? за границей — вот тут уже сам виноват
```

Индексация работает, сентинел читается, а тип в сигнатуре функции *документирует* контракт: «дай мне нуль-терминированное».

## Ручной проход до нуля

Длина такой строки считается циклом — как `strlen` в libc:

```zig
var n: usize = 0;
while (s[n] != 0) n += 1;
// n — длина без сентинела
```

## `std.mem.span` — мост в мир слайсов

Превратить sentinel-указатель в обычный слайс — `std.mem.span`:

```zig
const s: [*:0]const u8 = "hello";
const slice = std.mem.span(s);  // [:0]const u8, "hello"
slice.len == 5                  // сентинел в len не входит
```

Тип результата — `[:0]const u8`: слайс, у которого `slice[slice.len]` — гарантированный `0`. Получив слайс, ты в мире обычного Zig: `for`, `std.mem.eql`, всё работает.

## Зачем это нужно

- **C-интероп**: `open(2)`, `printf`, SQLite, Vulkan — везде `const char*`. `[*:0]const u8` даёт типобезопасную границу.
- **Один байт экономии**: длину хранить не надо — удобно для огромных таблиц строк.
- **Защита от себя**: `s[5] == 0` для `"hello"` проверяется типом; попытка отдать не-nul строку туда, где ждут `[*:0]`, не скомпилируется.

Обратная сторона: длина неизвестна → каждый `span` — O(n) проход. Поэтому внутри Zig-кода царствуют слайсы, а sentinel-строки живут на границе с C.
