# Optional-типы: `?T`

## null без NullPointerException

В C «не найдено» кодируют магическим значением: `-1`, `0`, `NULL`. Читатель кода обязан помнить конвенцию, компилятор — нет. В Zig отсутствие значения — часть типа: `?usize` — это «либо `usize`, либо `null`».

```zig
var maybe: ?usize = null;
maybe = 5;
```

`?T` — не указатель и не хак: это значение с битиком «есть/нет». Для указателей `?*T` — тот самый nullable-указатель из C, но теперь компилятор следит за проверкой.

## Развёртывание optional

`?T` нельзя использовать там, где ждут `T` — придётся сначала развернуть:

```zig
if (maybe) |v| {
    // v: usize — точно не null
} else {
    // ветка «пусто»
}

// или с умолчанием:
const v = maybe orelse 0;

// или «я уверен» — паника, если null:
const v = maybe.?;
```

Три основных инструмента: `if (opt) |v|` (захват значения), `orelse` (значение по умолчанию / ранний выход) и `.?` (ассерт «не null»). Четвёртый — `while (opt) |v|` для циклов с optional-условием, встретится в итераторах.

## `orelse` как ранний выход

`orelse` принимает не только значение — справа может стоять `return`, `break`, `unreachable`:

```zig
const idx = indexOfMax(xs) orelse return;  // выйти из функции, если null
```

Это стандартная идиома Zig: «разверни или уходи». Ей весь error handling построен (`try` — тот же принцип для ошибок, но это следующий модуль).

## Почему `?usize`, а не `-1`

Сравни контракты:

```zig
// C-стиль: -1 значит «пусто». Или значит? А если -2? Документация молчит.
fn indexOfMax_c(xs: []const i32) isize;

// Zig-стиль: тип отвечает сам.
fn indexOfMax(xs: []const i32) ?usize;
```

Второй вариант нельзя проигнорировать: если забыть проверить и сунуть результат в `xs[i]`, компилятор скажет «expected usize, found ?usize». Sentinel-подход молча даёт `xs[18446744073709551615]` — паника или UB.

## Индекс + значение в одном `for`

Для задачи «найди индекс» нужна форма с двумя захватами:

```zig
for (xs, 0..) |x, i| {
    // x — элемент, i — его индекс (usize)
}
```

Запомни порядок: сначала элемент, потом индекс. `0..` читается «индексы от нуля». Можно стартовать с другого числа: `for (xs, 1..) |x, i|` даст `i` начиная с 1 — иногда удобно для «номеров» вместо «индексов».

## Сравнения и максимум

Алгоритм «индекс максимума»: держи `best` — индекс лучшего на данный момент. Иди с первого элемента (или со второго, взяв `best = 0`), сравнивай `xs[i] > xs[best]` и обновляй. Пустой слайс — особый случай: `best` нечем инициализировать, поэтому его обрабатывают до цикла — через `if (xs.len == 0) return null;` или инициализацию `best = 0` с защитой.
