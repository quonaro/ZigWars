# anytype — «принимай что угодно»

Когда у параметра вместо типа стоит `anytype`, Zig выводит реальный тип из аргумента при каждом вызове. Функция фактически становится шаблоном: для `i32` компилятор сгенерирует одну версию, для `f64` — другую.

```zig
fn identity(x: anytype) @TypeOf(x) {
    return x;
}

test "любой тип" {
    try std.testing.expectEqual(42, identity(@as(i32, 42)));
    try std.testing.expectEqual('z', identity('z'));
}
```

## `@TypeOf`

`@TypeOf(expr)` возвращает тип выражения. Это главный инструмент рядом с `anytype`:

- `@TypeOf(a)` — тип одного параметра.
- `@TypeOf(a, b)` — «peer type resolution»: общий тип, к которому приводятся оба аргумента. Например, `u8` + `i32` → `i32`, `i32` + `f64` → `f64`.

```zig
pub fn add(a: anytype, b: anytype) @TypeOf(a, b) {
    return a + b; // оба операнда приводятся к общему типу
}
```

Вызов `add(@as(u8, 1), @as(f32, 0.5))` вернёт `f32` — Zig сам подобрал общий тип.

## Тип — это значение в comptime

Важно понять: `anytype` — не «обход системы типов». Компилятор подставляет **конкретный** тип на каждый вызов и проверяет всё как обычно. Если внутри функции сделать `a + b`, а `a` — строка, компиляция упадёт с нормальной ошибкой. Это «утиная типизация» — но на этапе компиляции, без потери безопасности.

## Когда what использовать

| Задача | Подход |
|--------|--------|
| Одинаковая логика для всех чисел | `a: anytype`, вернуть `@TypeOf(a)` |
| Смешанные типы | возврат `@TypeOf(a, b)` |
| Разная логика для разных типов | дженерик-функция `fn(comptime T: type) type` — следующая kata |

`@TypeOf` работает и в обычном коде: `const x: @TypeOf(y) = 0;` — удобно, когда тип длинный или должен повторять другой.

## Подводные камни

- `anytype`-аргументы всегда comptime-выводимы — функция с `anytype` не может быть вызвана через указатель без инстанцирования типа.
- Если две ветви `if` возвращают разные типы — компилятор попросит явный тип результата.
- `anytype` не значит «без типа»: попытка сделать `a[0]` для неиндексируемого типа — ошибка компиляции конкретного инстанцирования.
