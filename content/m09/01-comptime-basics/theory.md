# Comptime — программы внутри компилятора

В Zig компилятор умеет исполнять почти любой код ещё до того, как программа запустится. Результат встраивается в бинарник как константа — в рантайме вычислять уже ничего не нужно.

## `comptime`-параметры

Слово `comptime` перед параметром говорит: «значение должно быть известно при компиляции». Вызвать такую функцию с runtime-переменной нельзя — компилятор откажет.

```zig
pub fn comptimeSquare(comptime n: u32) u32 {
    return n * n;
}

test "площадь" {
    try std.testing.expectEqual(81, comptimeSquare(9));
    // const r = std.Random.DefaultPrng.init(0).random().int(u32);
    // comptimeSquare(r); // ОШИБКА: r известно только в рантайме
}
```

Весь код внутри такой функции выполняется компилятором — умножение `n * n` превращается в готовую константу `81` в бинарнике.

## `comptime var`

Обычная `var` внутри comptime-контекста живёт только во время компиляции. С её помощью строят циклы и таблицы:

```zig
fn factorial(comptime n: u32) u64 {
    comptime var result: u64 = 1;
    comptime var i: u32 = 2;
    inline while (i <= n) : (i += 1) {
        result *= i;
    }
    return result; // уже число, а не вычисление
}
```

Важная деталь: писать в `comptime var` разрешено только из **inline-цикла** — обычный `while` оставил бы запись в рантайме, а `comptime var` живёт лишь при компиляции. `inline while` разворачивает итерации — компилятор «размота́ет» цикл и запишет в бинарник готовое число. Ноль тактов в рантайме — по сути это макрос, но с типами и отладкой.

## `comptime` блоки

Ключевое слово `comptime` можно поставить перед любым блоком — тогда он гарантированно исполнится при компиляции:

```zig
const digits = comptime blk: {
    var buf: [10]u8 = undefined;
    for (&buf, 0..) |*b, i| b.* = '0' + @as(u8, @intCast(i));
    break :blk buf;
};
// digits — это "0123456789", вычисленное в бинарник заранее
```

## `inline for` и `inline while`

Родственник comptime: `inline for` / `inline while` разворачивают цикл — компилятор делает N копий тела, по одной на итерацию. Условие и диапазон должны быть comptime-известны, а `comptime var` внутри можно мутировать — каждая копия тела работает со своим подставленным значением:

```zig
inline for (0..4) |i| {
    // четыре отдельные копии тела с i = 0,1,2,3
}
```

В отличие от `comptime`, тело `inline for` работает и с runtime-данными — просто без проверки условия цикла на каждом шаге.

## Зачем это всё?

- **Константные таблицы**: факториалы, CRC-таблицы, таблицы синусов — считаются один раз при сборке.
- **Дженерики**: тип — тоже значение, и оно существует только в comptime (следующие kata).
- **Проверки на этапе компиляции**: `@compileError` вызывает ошибку сборки, если условие не выполнено.
