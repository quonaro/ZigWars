## Задание

### `fib` — поиск в comptime-таблице

```zig
pub fn fib(comptime n: u8) u64
```

Построй таблицу чисел Фибоначчи при компиляции: `fib(0) = 0`, `fib(1) = 1`, `fib(n) = fib(n-1) + fib(n-2)`. `u64` вмещает значения до `n = 92` включительно — таблица на 93 элемента покрывает всё, что можно протестировать. При `n > 92` используй `@compileError` с понятным сообщением.

Подсказка: таблицу удобно собрать блоком на уровне файла (инициализатор `const` на уровне файла и так исполняется в comptime — слово `comptime` перед `blk:` будет лишним):

```zig
const fib_table = blk: {
    var t: [93]u64 = undefined;
    // заполни…
    break :blk t;
};
```

### `rangeSum` — вариативная функция со стражём

```zig
pub fn rangeSum(comptime T: type, comptime lo: T, comptime hi: T) T
```

Сумма всех целых от `lo` до `hi` **включительно**. Если `lo > hi` — верни `0`. Если `T` не целочисленный тип — `@compileError` с сообщением вида `"rangeSum: нужен целочисленный тип, а не " ++ @typeName(T)`.

### Примеры

| Вызов | Результат |
|-------|-----------|
| `fib(10)` | `55` |
| `fib(0)` | `0` |
| `fib(90)` | `2880067194370816120` |
| `rangeSum(i32, 1, 10)` | `55` |
| `rangeSum(u8, 1, 100)` | `5050` (u8 переполнится? — нет, сумма вычисляется в `T`, но `5050` не влезает в `u8` — см. ограничения) |
| `rangeSum(i32, 5, 3)` | `0` |

### Ограничения

- `rangeSum` считает в типе `T` — не допускай переполнения в тестах: `rangeSum(u8, 1, 100)` дал бы `5050` и упал бы на overflow. Используй типы с запасом.
- `fib` должен работать **только** с comptime `n` (параметр `comptime n: u8` обеспечит это сам).
