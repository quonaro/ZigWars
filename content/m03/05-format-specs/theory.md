# Форматные строки и `alloc.print`

## Спецификаторы `std.fmt`

В Zig форматная строка — comptime-известная: `{...}` — это не «шаблон на рантайме», а жёстко проверенный при компиляции код. Спецификатор после двоеточия выбирает представление:

```zig
{s}     // строка / байты
{d}     // десятичное число
{x}     // шестнадцатеричное ({X} — большими буквами)
{b}     // двоичное
{o}     // восьмеричное
{c}     // байт как ASCII-символ
{*}     // указатель (адрес)
{any}   // «как-нибудь» — рекурсивный разбор любого типа
{e}     // научная нотация
```

Пустые `{}` — дефолтное форматирование типа.

## Точность и ширина

После `:` — опции: `[ширина][.точность]`. Для float точность — число знаков после запятой:

```zig
"{d:.2}"   // 98.5   -> "98.50"
"{d:.0}"   // 98.5   -> "99" (округление)
"{d:5}"    // 42     -> "   42"  — ширина 5, паддинг слева
"{d:0>5}"  // 42     -> "00042"  — заполнитель и выравнивание
"{s:>10}"  // "hi"   -> "        hi"
"{x:0>4}"  // 255    -> "00ff"
```

Формат `<`, `>`, `^` — выравнивание влево/вправо/по центру, символ перед ним — заполнитель (по умолчанию пробел).

## Экранирование скобок

Литеральная `{` или `}` пишется удвоением: `"{{}}"` → `{}`.

## `alloc.print` — строка в куче

Куда писать форматированный вывод? Вариант для этой задачи — прямо в свежий буфер:

```zig
const s = try alloc.print("{s} is {d}", .{ "zig", 17 });
defer alloc.free(s);
```

`alloc.print(fmt, args)` — метод `std.mem.Allocator`: выделяет буфер ровно под результат и возвращает `![]u8`. Аргументы — **кортеж** `.{a, b, c}` (анонимный struct-литерал).

> Не путай с устаревшим `std.fmt.allocPrint` — в 0.17 правильная форма именно `alloc.print`.

## Другие приёмники — на будущее

Тот же формат идёт в любой writer:

```zig
var w: std.Io.Writer = .fixed(&buf);   // запись в фиксированный буфер
try w.print("{d}", .{42});
```

Или собирай вручную через `std.ArrayList(u8)` + `appendSlice`/`print` — когда строку строят по кусочкам.

## `{any}` — спаситель при отладке

`{any}` печатает что угодно: структуры с полями, массивы, опционалы, даже enum'ы:

```zig
"{any}" на .{ .x = 1, .y = 2 }  ->  ".{ .x = 1, .y = 2 }"
"{any}" на @as(?u8, null)        ->  "null"
```

Для продакшн-текста подбирай точные спецификаторы, для отладки `{any}` незаменим.
