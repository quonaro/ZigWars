# Итерация по строке и switch

## `for` по байтам

Строка — слайс, поэтому `for` работает как с любым слайсом:

```zig
for (s) |byte| {
    // byte: u8 — один байт, а не «символ»
}

for (s, 0..) |byte, i| {
    // i: usize — индекс байта
}
```

Если нужно пройтись по подстроке — сначала нарежь слайс: `s[2..5]` — байты со 2 по 4 включительно.

## `switch` — твой главный инструмент

`switch` в Zig — это выражение, и оно обязано быть **исчерпывающим** (exhaustive): все случаи покрыты, иначе `else`.

```zig
const is_vowel = switch (byte) {
    'a', 'e', 'i', 'o', 'u' => true,
    else => false,
};
```

Можно с диапазонами и блоками:

```zig
switch (byte) {
    'a'...'z' => { /* маленькая латинская буква */ },
    '0'...'9' => { /* цифра */ },
    else => {},
}
```

Обрати внимание: `'a'` — это **байт** (`u8`, comptime_int на самом деле), а `"a"` — строка из одного байта. Для сравнения отдельных байт используй одинарные кавычки.

## Честно про ASCII и Unicode

`for (s)` идёт по **байтам**. Для ASCII это совпадает с символами — и жизнь прекрасна. Но `'я'` в UTF-8 — два байта `0xD1 0x8F`, и один `for` увидит их как два отдельных «мусорных» байта. Настоящая итерация по юникодным кодпоинтам — это `std.unicode.Utf8View` / `utf8Decode` — история сложнее и заслуживает отдельного модуля. В этой задаче работаем строго с ASCII-гласными.

Хорошая новость: UTF-8 спроектирован так, что байты `0x00`–`0x7F` всегда означают ASCII-символы и не встречаются внутри многобайтовых символов. Так что «посчитать ASCII-гласные в UTF-8 строке» — корректная операция.

## Накопление результата

```zig
var count: usize = 0;
for (s) |byte| {
    if (byte == 'a' or byte == 'e') count += 1;
}
return count;
```

`usize` — канонический тип для счётчиков и индексов: его ширина совпадает с указателем.
