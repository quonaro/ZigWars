# Структуры и методы

## `struct` — главный тип данных

Почти все пользовательские типы в Zig — это `struct`. Объявление похоже на C, но структура в Zig — это ещё и «контейнер»: внутрь можно класть константы, типы и функции.

```zig
const Point = struct {
    x: f64,
    y: f64,
};

const p = Point{ .x = 3.0, .y = 4.0 }; // литерал: все поля обязаны получить значение
p.x                                    // чтение поля
```

Поля без значения по умолчанию **обязаны** быть проинициализированы — никакого «мусора из памяти», как в C (на самом деле можно, через `undefined`, но это отдельная история про unsafe).

## Значения по умолчанию

Полю можно дать дефолт — тогда его можно пропускать в литерале:

```zig
const Config = struct {
    retries: u8 = 3,
    verbose: bool = false,
};

const cfg = Config{ .verbose = true }; // retries = 3
const empty = Config{};                // всё по дефолту
```

Идиома «конфиг с дефолтами» встречается в std повсеместно: `fs.File.OpenFlags`, `DebugAllocator(.{})` — всё это структуры с дефолтными полями. `Config{}` читается как «дефолтный конфиг».

## Методы — это просто функции внутри struct

В Zig нет ключевого слова `method` и нет скрытого `this`. Метод — функция, объявленная внутри структуры, у которой первый параметр имеет тип этой структуры:

```zig
const Point = struct {
    x: f64,
    y: f64,

    pub fn add(self: Point, other: Point) Point {
        return .{ .x = self.x + other.x, .y = self.y + other.y };
    }
};
```

Имя `self` — чистая конвенция, компилятору всё равно. Раз параметр первый и типа `Point`, вызов через точку работает автоматически:

```zig
const c = a.add(b);          // то же, что Point.add(a, b)
```

Это называется UFCS-подобный сахар: `x.f(y)` === `T.f(x, y)`, где `T` — тип `x`. Поэтому `list.deinit(alloc)` — обычная функция `deinit`, а не магия классов.

Мутирующий метод принимает указатель на себя:

```zig
pub fn scale(self: *Point, k: f64) void {
    self.x *= k;
    self.y *= k;
}
// const p — не вызовешь, нужен var p
```

## Возвращаем `.{}` без имени типа

В `add` выше мы вернули `.{ .x = ..., .y = ... }` — **анонимный литерал структуры**. Тип выводится из сигнатуры `-> Point`. То же работает в аргументах: `distance(a, .{ .x = 0, .y = 0 })`.

Анонимные структуры вообще — полноценные типы: `const pair = .{ .x = 1, .y = 2 };` создаёт безымянную структуру. Но передавать такие типы между функциями неудобно (у каждого литерала свой тип), поэтому для API всегда давай структуре имя.

## Файл = структура

Тонкий момент: `solution.zig` сам по себе — структура! `const sol = @import("solution.zig")` возвращает тип структуры, а `sol.distance` — доступ к её `pub`-члену. Поэтому `@import` того же файла ничего не стоит: Zig просто видит все `pub` объявления.

## `@sqrt` и `std.math`

Квадратный корень есть и как builtin `@sqrt(x)`, и как `std.math.sqrt(x)` — оба работают в 0.17. Builtin сразу возвращает тип аргумента, `std.math` добавляет обёрток и edge-cases. Для геометрии берите что нравится; `std.math.pi` — константа π из std.
