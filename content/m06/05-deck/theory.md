# `enum(u8)`, композиция типов, карты

## Enum с явным типом тега

По умолчанию компилятор сам выбирает целый тип под теги enum. Но тип можно зафиксировать — `enum(u8)`:

```zig
const Rank = enum(u8) {
    two = 2, three = 3, four = 4, five = 5, six = 6, seven = 7,
    eight = 8, nine = 9, ten = 10,
    jack = 11, queen = 12, king = 13, ace = 14,
};
```

Зачем? Три причины:

1. **Размер гарантирован** — `u8` занимает ровно байт, важно для сериализации и FFI.
2. **Значения осмысленны** — `two = 2`…`ace = 14` отражают старшинство карт. Теперь `@intFromEnum(Rank.ace)` возвращает честную «силу» карты — сравнивать достоинства можно числами, без switch-таблиц.
3. **Контракт с внешним миром** — протоколы и форматы файлов часто требуют конкретные коды.

Все теги должны влезать в указанный тип: `enum(u8)` с `x = 300` не скомпилируется. Теги можно задавать явно, можно опускать (тогда +1 к предыдущему), можно смешивать:

```zig
const V = enum(u8) { a = 10, b, c = 40, d }; // b = 11, d = 41
```

## `@intFromEnum` и обратно

`@intFromEnum(Rank.king)` → `13` (тип — тот самый `u8` из объявления). Обратно — `@enumFromInt(n)`, тип берётся из контекста. С «осмысленными» тегами сравнение `Rank` сводится к сравнению `u8`:

```zig
if (@intFromEnum(a.rank) > @intFromEnum(b.rank)) { ... }
```

Вместо 12-строчного `switch` — одно сравнение. Красота.

## Композиция: struct из enum'ов

По отдельности `Suit` и `Rank` — маленькие перечисления. Карта — просто их произведение:

```zig
const Suit = enum { spades, hearts, diamonds, clubs };

const Card = struct {
    rank: Rank,
    suit: Suit,
};
```

`Card` — 2 байта: `u8` под rank + тег под suit. Литерал:

```zig
const c = Card{ .rank = .ace, .suit = .spades };
// короче: .{ .rank = .ace, .suit = .spades }
```

Это и есть моделирование в Zig: никаких классов и наследования — маленькие типы, сложенные вместе. Нужен «козырь» — это `Suit`, переданный параметром функции, а не специальное состояние.

## Логика «beats» без боли

Правило карточной игры: карта `a` бьёт `b`, если

- масти совпадают и `rank(a) > rank(b)`, **или**
- масти разные, но `a` — козырь, а `b` — нет.

Козырь против козыря — обычное сравнение по старшинству (они «одной масти» по смыслу). Некозырь козыря не бьёт никогда. Всё это — пара проверок `==` и `>`, без всяких switch: enum'ы сравниваются на равенство напрямую (`a.suit == b.suit`), а порядок даёт `@intFromEnum`.

## Кстати: `@intFromEnum` на обычном enum

Для `Suit` тоже работает — вернёт индекс 0..3. Просто для мастей индекс ничего не значит, и мы им не пользуемся.
