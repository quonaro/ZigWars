# ArenaAllocator: память пачками

## Проблема

Есть класс задач, где память выделяется сотнями мелких кусков — распарсить конфиг, построить AST, сгенерировать ответ сервера — и вся она нужна **до конца операции**, после чего не нужна вся целиком. Трекать `free` для каждого куска утомительно и чревато утечками.

## Решение: арена

`std.heap.ArenaAllocator` оборачивает другой аллокатор и отдаёт память большими блоками внутри себя. Каждая аллокация — дёшевая (подвинуть указатель в текущем блоке). А освобождение — одно на всех: `arena.deinit()` возвращает всё выделенное разом в родительский аллокатор.

```zig
var arena = std.heap.ArenaAllocator.init(std.heap.page_allocator);
defer arena.deinit();              // освобождает ВСЁ, что выделили из a
const a = arena.allocator();

const x = try a.create(i32);       // free не нужен!
const buf = try a.alloc(u8, 100);  // и здесь не нужен
const s = try a.dupe(u8, "tmp");   // и здесь
```

Индивидуальный `free` в арене — почти no-op (кроме последнего выделенного блока). Поэтому паттерн такой: в арену сваливаем всё временное, а `deinit` срабатывает один раз при выходе из функции/обработки запроса.

## Когда арена — идеальный выбор

- **Запрос/операция с чётким концом**: обработать HTTP-запрос, пройти тест, скомпилировать файл. Конец операции = `deinit`.
- **Фазовая работа**: загрузил уровень игры → арена уровня; вышел → `deinit`.
- **Много мелких объектов без индивидуального времени жизни**: узлы дерева, строки парсера.

## Когда арена НЕ подходит

- Долгоживущие объекты среди временных: арена держит **всё** до `deinit`. Освободить один объект нельзя — накопится мусор.
- Циклы, где память растёт неограниченно: «арена на итерацию» — да, «одна арена на миллион итераций» — утечка по сути.

## Арена поверх арены?

Да, арену можно инициализировать любым аллокатором — хоть `page_allocator`, хоть другой ареной, хоть `testing.allocator` (так и делают в тестах: детектор утечек проверит, что `deinit` вернул все байты).

```zig
// в тесте
var arena = std.heap.ArenaAllocator.init(std.testing.allocator);
defer arena.deinit();
const a = arena.allocator();
```

Типичный баг: функция принимает `alloc` и возвращает выделенный из него срез. Если вызывающий передал арену — `free` результату не нужен, но и не повредит. Если передал обычный аллокатор — `free` обязателен. Это контракт: **функция не знает, что за аллокатор ей дали, и не должна знать**.
