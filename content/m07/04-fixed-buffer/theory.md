# FixedBufferAllocator: куча без кучи

## Что это

`std.heap.FixedBufferAllocator` — аллокатор, который «выделяет память» из буфера, который ты сам ему дал. Буфер может лежать на стеке, в статике, где угодно — куча вообще не участвует.

```zig
var buf: [1024]u8 = undefined;
var fba = std.heap.FixedBufferAllocator.init(&buf);
const a = fba.allocator();

const s = try a.dupe(u8, "hello");     // живёт внутри buf
const n = try a.create(i32);           // тоже там
```

Это обычный `std.mem.Allocator` — его можно передавать в любую функцию, которая ждёт аллокатор. Внутри — просто указатель «куда доехали»: аллокация — это `ptr += size` плюс выравнивание, очень быстро и предсказуемо.

## Почему `error.OutOfMemory` — это нормально

Память кончается ровно тогда, когда кончается буфер — `fba` честно отвечает `error.OutOfMemory`. Никаких `NoSpaceLeft`, никакой магии: тот же контракт, что у настоящей кучи. Поэтому код, работающий с любым `Allocator`, автоматически умеет работать с фиксированным буфером.

## Зачем это нужно

- **Embedded/без кучи**: на микроконтроллерах и в freestanding-коде кучи может не быть вообще. Статический буфер + FBA — и у тебя «аллокатор».
- **Горячие пути**: аллокация за O(1) без syscall'ов, логирование, сбора временных строк внутри цикла, где аллокации в кучу — лишние такты.
- **Предсказуемость**: максимум памяти задан заранее и виден в коде. Переполнение — управляемая ошибка, а не рост RSS.
- **Сброс за O(1)**: `fba.reset()` «освобождает» всё разом, как мини-арена.

## Практический приём: «собери в buf»

Частая задача — склеить/собрать данные в заранее выделенный срез. С FBA это читается как обычная работа с аллокатором:

```zig
var buf: [64]u8 = undefined;
var fba = std.heap.FixedBufferAllocator.init(&buf);
const out = try std.mem.concat(fba.allocator(), u8, &.{ a, b });
// out — срез внутри buf; free не нужен
```

Или совсем без аллокатора — вручную: проверить `a.len + b.len <= buf.len`, два `@memcpy`, вернуть `buf[0..total]`. Оба варианта идиоматичны; FBA-вариант лучше масштабируется на большее число кусков.

## Важно про владение

Данные, «выделенные» из FBA, живут столько, сколько живёт исходный буфер. `buf` на стеке функции → вернувшийся `out` нельзя отдавать наружу после `return` — классический dangling. Индивидуальный `free` почти бесполезен (освобождает только «последний» кусок), поэтому обычно `free` на таких срезах просто не делают.
