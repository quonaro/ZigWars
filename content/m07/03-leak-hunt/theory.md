# Утечки и как их ловить

## `std.testing.allocator` — детектор утечек

В тестах Zig принято использовать `std.testing.allocator`. Это не просто «какой-то аллокатор», а `DebugAllocator` под капотом: он записывает каждую аллокацию и каждый `free`, и когда тест завершается — сверяет баланс. Выделил и не освободил? Тест красный, со стектрейсом до места утечки.

```zig
test "пример" {
    const alloc = std.testing.allocator;
    const buf = try alloc.alloc(u8, 64);
    // забыли alloc.free(buf) — тест упадёт с "memory leak"
}
```

За пределами тестов то же самое делает `std.heap.DebugAllocator(.{})` вручную: `defer _ = gpa.deinit();` напечатает отчёт об утечках в stderr.

## `defer` — для временного, `errdefer` — для «отдали наружу»

`defer` срабатывает при **любом** выходе из скопа — и по `return`, и по ошибке. Идеален для временных буферов, которые не покидают функцию:

```zig
const tmp = try alloc.alloc(u8, n);
defer alloc.free(tmp);        // проживёт до конца функции, потом умрёт
```

`errdefer` срабатывает **только если функция вернула ошибку**. Он для ресурса, который при успехе переходит вызывающему (тот будет его освобождать), а при провале должен умереть здесь:

```zig
const out = try alloc.alloc(i32, n);
errdefer alloc.free(out);     // если дальше что-то упадёт — не утекает
return out;                   // при успехе errdefer НЕ срабатывает
```

Без `errdefer` классический баг: выделили буфер, следующая операция вернула ошибку — буфер потерян навсегда.

## Множественные выделения = множественные пути провала

Каждая новая `try alloc.*` добавляет путь выхода. Дисциплина простая: **сразу после успешной аллокации решай её судьбу** — `defer` (умрёт здесь), `errdefer` (умрёт при ошибке) или передача владения в `return`.

## Ловушки

- **`free` со «срезом-подсрезом»**: `alloc.free(buf[0..k])` вместо `buf[0..n]` — инвалидный free. Длина должна совпадать с выделенной.
- **Двойной free**: `DebugAllocator` ловит и его.
- **Утечка только на error-пути**: самый коварный вид — обычные тесты проходят, а баг ждёт `OutOfMemory`. Для таких случаев есть `std.testing.FailingAllocator` (заставляет N-ю аллокацию провалиться) и `std.testing.checkAllAllocationFailures` — прогоняет функцию, заставляя провалиться каждую аллокацию по очереди, и проверяет отсутствие утечек на каждом пути.

## Ментальная модель

Считай каждый выделенный байт «долгом». На каждом выходе из функции долг либо погашен (`free`), либо передан дальше (возврат с контрактом «вызывающий освободит»). `defer`/`errdefer` — это расписки, которые ты выписываешь в момент займа.
