## Задание — почини утечку!

В `solution.zig` уже есть **рабочая, но дырявая** функция `dedupCopy` — она возвращает отсортированную копию `xs` без подряд идущих дубликатов (уникальные значения подряд схлопываются).

```zig
pub fn dedupCopy(alloc: std.mem.Allocator, xs: []const i32) ![]i32
```

Логика верная, но память утекает — и на успешном пути, и при ошибке выделения. `std.testing.allocator` это видит, а один из тестов прогоняет функцию через `checkAllAllocationFailures`.

### Твоя задача

Добавить правильные `defer`/`errdefer`, **не меняя алгоритм**:

- Временный буфер `tmp` используется только внутри функции — ему нужен `defer`.
- Возвращаемый `out` принадлежит вызывающему — тот делает `free`. Но если бы между его аллокацией и `return` была падающая операция — понадобился бы `errdefer`.

### Примеры

| Вход | Результат |
|------|-----------|
| `[3, 3, 1, 2, 2]` | `[1, 2, 3]` |
| `[5, 5, 5]` | `[5]` |
| `[]` | `[]` |
